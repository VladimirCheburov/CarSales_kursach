1. ВВЕДЕНИЕ
================================================================================

Актуальность
------------
Современные организации используют несколько информационных систем одновременно:
веб-порталы, CRM, мобильные каналы коммуникации. Без интеграции данные
дублируются, уведомления запаздывают, пользователи вынуждены переключаться
между интерфейсами. Для автодилера или маркетплейса объявлений критично
оперативно информировать продавцов о запросах покупателей и давать клиентам
быстрый доступ к каталогу с мобильного устройства.

Цель проекта
------------
Разработать и реализовать прототип интеграции между двумя ИС в одной
организации: веб-платформой CarSales (Django) и Telegram-ботом как второй
(смоделированной) информационной системой мобильного доступа и push-уведомлений.

Задачи
------
1. Описать функциональность обеих ИС, данные и точки интеграции.
2. Спроектировать архитектуру обмена (REST API, JSON, HTTP).
3. Реализовать прототип: API интеграции, бот, асинхронные уведомления.
4. Провести тестирование и оценить метрики latency и throughput.

================================================================================
2. АНАЛИТИЧЕСКАЯ ЧАСТЬ
================================================================================

2.1. ИС №1 — Веб-платформа CarSales (реальная система)
--------------------------------------------------------
Назначение: публикация объявлений о продаже автомобилей, поиск, избранное,
отзывы, переписка покупатель–продавец, новости.

Основные сущности (ERD):
- User, Profile — пользователи и профили продавцов
- Auto, Brand, Region, SellStatus — каталог автомобилей
- Favorite, Review — избранное и отзывы
- Message — переписка по объявлению
- New (news) — новостной блок

Интерфейсы:
- Web UI (HTML, Django templates)
- REST API (/api/autos/, /api/brands/, …) — DRF
- Integration API (/api/integration/…) — для второй ИС

2.2. ИС №2 — Telegram-бот CarSales Bot (смоделированная система)
------------------------------------------------------------------
Назначение: мобильный канал для пользователей организации:
- быстрый поиск автомобилей;
- просмотр карточки объявления;
- доступ к избранному;
- отправка сообщений продавцу;
- получение push-уведомлений о новых сообщениях с сайта.

Данные бота не хранит самостоятельно — работает как клиент Integration API
(stateless), что соответствует паттерну «тонкий клиент + центральная ИС».

2.3. BPMN-сценарии (текстовое описание)
---------------------------------------

Сценарий A — Синхронный поиск (real-time):
  Пользователь → /search BMW → Bot → HTTP GET → Django → SQLite → JSON → Bot → Telegram

Сценарий B — Привязка аккаунта:
  Пользователь (web) → GET /api/integration/link-token/ → код
  Пользователь (Telegram) → /link <код> → POST /api/integration/link/ → Profile.telegram_chat_id

Сценарий C — Асинхронное уведомление:
  Покупатель (web) → POST send_message → Message.save → Celery task → Telegram API → продавец

3. ПРОЕКТНАЯ ЧАСТЬ
================================================================================

3.1. Выбор подхода интеграции
------------------------------
Выбран: прямая интеграция через REST API (точка-точка) + асинхронная очередь
(Celery/Redis) для уведомлений.

Обоснование:
- Небольшое число систем (2) — ESB избыточен.
- REST/JSON — стандарт de facto, простая отладка (Swagger /api/docs/).
- Celery разгружает веб-запрос при отправке Telegram-сообщений.

3.2. Архитектура
----------------

  [Telegram Client] <---> [Telegram Bot API] <---> [Telegram Bot Process]
                                                          |
                                    HTTP + X-Integration-Key
                                                          |
  [Browser] <---> [Django Web + DRF] <---> [SQLite DB]
                          |
                    [Celery Worker] ---> [Telegram Bot API]

3.3. Спецификация Integration API
---------------------------------

Базовый URL: http://127.0.0.1:8000/api/integration/

Аутентификация: заголовок X-Integration-Key (общий секрет для бота и сервера).

| Метод | URL                        | Описание                          |
|-------|----------------------------|-----------------------------------|
| GET   | /link-token/               | Код привязки (session auth, web)  |
| POST  | /link/                     | Привязать telegram_chat_id        |
| GET   | /autos/search/?q=          | Поиск автомобилей (до 10)         |
| GET   | /autos/{id}/               | Карточка автомобиля               |
| GET   | /favorites/?telegram_chat_id= | Избранное пользователя         |
| GET   | /messages/inbox/?telegram_chat_id= | Непрочитанные сообщения    |
| POST  | /messages/                 | Отправить сообщение продавцу      |

Формат обмена: JSON, протокол HTTP/1.1.

Пример ответа поиска:
{
  "id": 1,
  "brand": "BMW",
  "model": "X5",
  "year": 2020,
  "price": 3500000,
  "mileage": 45000,
  "region": "Москва",
  "sell_status": "В продаже",
  "description": "..."
}

3.4. Нефункциональные требования (ГОСТ Р ИСО/МЭК 25010-2015)
-------------------------------------------------------------
- Безопасность: API-ключ интеграции; одноразовый token привязки аккаунта.
- Производительность: асинхронная отправка уведомлений через Celery.
- Надёжность: retry до 3 раз при ошибке Telegram API.
- Сопровождаемость: OpenAPI-документация основного API (/api/docs/).

4. РЕАЛИЗАЦИОННАЯ ЧАСТЬ
================================================================================

4.1. Стек технологий
--------------------
- Python 3.11+, Django 5.1, Django REST Framework
- SQLite (прототип), Celery + Redis
- python-telegram-bot 21.x
- requests — HTTP-клиент бота

4.2. Ключевые файлы реализации
------------------------------
- cars/models.py — поля Profile: telegram_chat_id, telegram_link_token
- cars/integration_api.py — REST endpoints интеграции
- cars/integration_auth.py — проверка X-Integration-Key
- cars/signals.py — post_save Message → Celery
- cars/tasks.py — notify_telegram_new_message
- bots/telegram_bot.py — логика Telegram-бота
- cars/management/commands/runtelegrambot.py — запуск бота

4.3. Команды бота
-----------------
/start, /help, /link, /search, /car, /favorites, /inbox, /message

4.4. Инструкция запуска прототипа
---------------------------------
1. pip install -r requirements.txt
2. python manage.py migrate
3. python scripts/fill_db.py  (если БД пустая)
4. python manage.py runserver
5. Задать переменные из .env.example
6. python manage.py runtelegrambot
7. (опционально) celery -A carsales worker -l info

4.5. Тестовый план
------------------
| ID  | Тест-кейс                              | Ожидание              |
|-----|----------------------------------------|-----------------------|
| T1  | GET search с валидным API-ключом       | 200, список авто      |
| T2  | GET search с неверным ключом           | 403 Forbidden         |
| T3  | POST link с валидным token             | 200, привязка chat_id |
| T4  | POST link с неверным token             | 404                   |
| T5  | POST message от привязанного пользователя| 201 или 400 (сам себе)|
| T6  | Создание Message на сайте              | Celery → Telegram     |
| T7  | /search в боте                         | Ответ с объявлениями  |

Автотест: python scripts/test_integration_api.py (при запущенном runserver)

4.6. Метрики (для отчёта / демонстрации)
----------------------------------------

Latency (задержка):
- Измерение: время от HTTP-запроса бота до получения JSON (search, 10 записей).
- Ожидаемый порядок на localhost: 20–80 ms (без учёта Telegram).
- Команда: curl -w "%{time_total}" -H "X-Integration-Key: ..." \
    "http://127.0.0.1:8000/api/integration/autos/search/?q=BMW"

Throughput (пропускная способность):
- Инструмент: Apache Bench (ab) или locust.
- Пример: ab -n 100 -c 10 -H "X-Integration-Key: dev-integration-key-change-me" \
    "http://127.0.0.1:8000/api/integration/autos/search/?q="
- На прототипе SQLite: ~50–150 req/s (зависит от железа).

4.7. Риски и улучшения
----------------------
| Риск                         | Мера снижения                          |
|------------------------------|----------------------------------------|
| Утечка INTEGRATION_API_KEY   | Хранение в .env, ротация ключей        |
| SQLite при нагрузке          | PostgreSQL в production                |
| Telegram недоступен          | Retry + dead-letter queue в Celery     |
| Нет JWT для пользователя     | Добавить DRF Token/JWT для mobile API  |

5. ЗАКЛЮЧЕНИЕ

В ходе проекта разработан прототип интеграции между веб-платформой CarSales
и Telegram-ботом. Реализованы сценарии синхронного обмена (поиск, карточки,
